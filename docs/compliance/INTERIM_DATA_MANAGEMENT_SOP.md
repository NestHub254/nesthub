# Interim NestHub data-management operating procedure

**Status:** DRAFT — internal SIONA procedure  
**Last updated:** 10 November 2026  
**Applies until:** Signed DPA and final retention schedule supersede this interim SOP

## 1. Purpose

Describe how SIONA staff handle NestHub-related personal data while providing technology, hosting and privacy-administration support.

## 2. Principles

- Minimum necessary access.
- No use of NestHub customer data for SIONA marketing.
- Do not invent controller roles beyond documented arrangements.
- Prefer written instructions for processor activities.

## 3. Intake

1. Privacy / deletion requests arriving via NestHub channels (`hello@nesthub.app` / NestHub phone) are logged.
2. Identity verification is completed before fulfilment.
3. Responsible controller for each record class is identified using the responsibility matrix.

## 4. Fulfilment

1. NestHub product records: NestHub leads; SIONA assists on systems SIONA operates.
2. SIONA infrastructure / compliance-support records: SIONA executes deletion or anonymisation where lawful.
3. Retention holds are documented before refusing full deletion.
4. Confirmation email is sent without exposing third-party personal data.

## 5. Records

Keep an internal ticket log (request date, verification method, outcome, systems touched). Do not commit personal request contents to git.
